Challenge 2

  1. Can you name the nine HTTP request methods?
    1. GET - fetches a resource from the server - body, + safe, + idempotent
    2. POST - creates a new resource associated with the URI, or performs some other operation using the data provided by the client + body, - safe, - idempotent
    3. PUT - updates (or creates) the resource associated with the URI + body, - safe, + idempotent
    4. DELETE - deletes the resource associated with the URI + body, - safe, + idempotent
    5. PATCH - updates the resource using the data provided in the body of the request + body, - safe, - idempotent
    6. OPTIONS - returns the "communications options" (gen. methods) available for the resource (not always supported) - body, + safe, + idempotent
    7. HEAD - returns the headers that would accompany the resource without the content (gets metadata) - body, + safe, + idempotent
    8. TRACE - debugging method that provides information on the servers that process the request and response - body, + safe, + idempotent
    9. CONNECT - establishes a connection to the resource / server not REST
  2. Pick three and describe what these request types do? See GET, POST, PUT above
  3. Which request only retrieves data from a server? GET

IP Addresses used by programs to identify hosts and thus to communicate with servers; IP addresses are frequently obtained by translating from host names using calls to library functions, which may either translate explicitly from a name to an address or make use of such a call in creating a channel through which data may be exchanged with a server.
  2. URI & URL A URI (uniform resource identifier) provides a way of specifying a resource on the internet. URIs are divided into URLs (uniform resource locations), which specify how to access a resource, and URNs (uniform resource names), which provide a unique identifier that can continue to be used to refer to the resource regardless of where (or if) it can be accessed at a particular point in time.
  3. DNS a domain name server translates between the name of a host and the associated IP address(es); host names have advantages when it comes to storing locations and interacting with users, while the internet protocol (the IP in TCP/IP) makes use of numeric IP addresses.
Are they different to traditional servers?
The term "cloud platform" basically refers to a network of servers that provide access to computing resources to clients. These resources include storage, processing, and software resources via public APIs (often based on HTTP). Unlike more traditional server environments, these resources are not typically associated with a single host machine that processes all client requests. Cloud computing often makes use of microservices, which implement parts of an application as small(ish), self-contained, network-accessible components. These are not typically implemented as long-lived server tasks. Instead, they often run on short-lived containers that ideally provide the minimum required to run a server that provides the service, or are "serverless", in the sense that the microservice is implemented as small pieces of code that run in response to events such as requests for services made by clients through the cloud provider. needs reviewing

Challenge 4: Testing HTTP Status Codes

Using our API & the documentation go to: https://reqres.in/api/users/
  1. Change the parameter when searching users with the API.
    See valid parameters below for results of making requests with different valid parameters. Response code is 200 ("200 OK").
  2. Add an incorrect parameter.
    All of the requests involving incorrect parameters resulted in a response code of 200 ("200 OK") and a response body containing JSON matching some variation of the request.
    1. Adding an incorrect parameter to a valid query does not change the result. The following produce the same result:
      • https://reqres.in/api/users?per_page=1&page=5&ziggy=woo
      • https://reqres.in/api/users?per_page=1&page=5.
    2. Setting a numeric parameter to a non-numeric value or 0 also results in the parameter being treated as if the default value had been specified.
    3. Negative values for page or per_page specify an offset from the end of the result set; e.g. per_page=0 or per_page=cat are treated as per_page=6.
  3. Make a call to a route that doesn't exist
    • Non-existent user or non-numeric userid (e.g. https://reqres.in/api/users/99 or https://reqres.in/api/users/jim): code "404", message "Not Found" JSON empty object as body "{}".
    • Additional components added to path (e.g. https://reqres.in/api/1/hello): code "404", message "Not Found"
  4. Add an incorrectly formed JSON to POST or PUT requests
    In either case, the status code and message are "404 Bad Request" with an HTML body containing a page with an error message, even if the "Accept" header is set to "application/json".
  5. Remove some/all headers from a request
    • Using postman, removing all but the mandatory headings that are added by the site, a "GET" request returns the same response.
    • This would be worth trying with a site that supports responses in either HTML or JSON format.
